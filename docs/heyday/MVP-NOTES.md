# HeyDay MVP 구현 메모

PRD v1.1(`docs/heyday/PRD.md`)의 어느 항목이 코드의 어디에 해당하는지,
그리고 무엇을 일부러 만들지 않았는지를 적어둔다.

## 실행

```bash
npm install     # 최초 1회
npm run dev
```

브라우저에서 <http://localhost:3000/heyday>

기존 AI 추천도 진단 서비스와 같은 Next.js 앱 안에 `/heyday` 경로로 들어 있다.
별도 저장소나 서버가 필요 없고, 배포도 기존과 동일하다.

## 화면

| 단계 | 경로 | PRD |
|---|---|---|
| 홈 | `/heyday` | Screen 1 |
| 활동 선택 | `/heyday/activity?c=` | Screen 2 |
| 날짜·시간 | `/heyday/when` | Screen 3 |
| 지역 | `/heyday/where` | Screen 3 |
| Mate 목록 | `/heyday/mates` | Screen 4 |
| Mate 상세 | `/heyday/mates/[id]` | Screen 5 |
| 예약 요청 | `/heyday/request/[id]` | 9장 |
| 예약 완료 | `/heyday/done/[id]` | 12장 |
| 검증 결과 | `/heyday/insights` | 14장 |

예약까지 사용자가 거치는 선택은 5단계다(활동 → 언제 → 어디서 → 메이트 → 요청).

### 흐름 상태를 URL에 두는 이유

선택값은 전부 쿼리스트링(`c`, `a`, `d`, `t`, `r`)에 들어간다.
5060 사용자는 브라우저 뒤로가기를 자주 쓰는데, 상태를 메모리에만 두면 뒤로 갔을 때
고른 것이 사라져 처음부터 다시 해야 한다. URL에 두면 뒤로가기·새로고침·링크 공유가
모두 그냥 동작한다. 사용자 테스트 중 특정 화면을 다시 보여주기도 쉽다.

### 조건에 맞는 Mate가 없을 때

목 데이터가 8명이므로 활동·지역·시간을 모두 만족하는 Mate가 없는 조합이 생긴다.
이때 빈 화면을 보여주면 검증이 거기서 끊긴다. 그래서 활동이 맞는 Mate는 모두 보여주되
무엇이 안 맞는지를 카드에 그대로 적는다("종로구는 활동 지역이 아니에요").
사용자가 시간을 바꿔서라도 특정 Mate를 고르는지 자체가 'Mate 선택 기준'에 대한
데이터가 된다.

## 검증 데이터

`/heyday/insights`에서 본다. APP_PASSWORD가 설정된 배포 환경에서는 로그인 뒤에만
열린다(요청자 연락처가 들어 있기 때문). 서비스 화면 `/heyday/*`는 공개다.

기록하는 것:

- `heyday_events` — 화면 도달과 선택. 브라우저가 만든 임의 식별자와 화면 이름뿐이다.
- `heyday_bookings` — 예약 요청. 이름·연락처·메모·가격·재이용 의향.

**North Star**(가격 공개 후 예약요청 전환율)는
`price_viewed`(Mate 목록 도달) 세션 대비 `booking_requested` 세션으로 계산한다.
가격은 Mate 카드에서부터 그대로 노출되므로, 목록에 도달한 사용자는 전원 가격을 본 것이다.

MVP가 답해야 할 네 질문과의 대응:

| 질문 | 보는 숫자 |
|---|---|
| 무엇을 가장 먼저 하고 싶어 하는가 | 가장 많이 고른 분야 / 활동 |
| 어떤 Mate를 선택하는가 | 가장 많이 본 메이트, 실제로 요청받은 메이트 |
| 얼마까지 지불하는가 | 요청된 가격대 |
| 다시 이용하는가 | 완료 화면의 재이용 의향 |

## 일부러 만들지 않은 것 (PRD 13장)

회원가입, 신분증 인증, 결제, 실시간 GPS, 실시간 채팅, AI 추천, 관리자 페이지.
간병·의료·금융 관련 활동은 카테고리에 넣지 않았고, 홈 하단에 다루지 않는다고 적어뒀다.

인증 배지는 UI 표현만 있고 실제 검증 시스템은 없다. 상세 화면에 '시범 서비스 화면'
이라고 적어 사용자가 오인하지 않게 했다.

Mate 사진은 스톡 사진 대신 일러스트 아바타를 쓴다. 실존하지 않는 목 데이터에 진짜
사람 사진을 붙이면 검증 과정에서 사용자를 속이게 된다.

## 목 데이터 바꾸기

`lib/heyday/data.ts` 한 파일에 카테고리·활동·지역·Mate 8명이 모두 들어 있다.
가격 가설을 바꿔 반응을 보려면 이 파일의 `price`만 고치면 된다.
A/B로 가격대를 달리 보여주고 `/heyday/insights`에서 전환율을 비교하는 방식으로
'적정 가격'(PRD 14장)에 접근할 수 있다.

## 디자인 토큰

`tailwind.config.ts`의 `heyday`(주황), `sand`(미색 바탕), `ink`(글자), `leaf`(인증)
네 가지만 쓴다. 공통 클래스는 `app/globals.css`의 `@layer components` 안에 있다
(`.hd-btn-primary`, `.hd-card`, `.hd-input` 등).

- 터치 타깃 최소 56px, 본문 17px, 제목 28~32px
- 병원의 파랑도, AI 서비스의 보라 그라데이션도 쓰지 않는다
- 화면당 질문은 하나, 핵심 행동도 하나
