# HeyDay PRD v1.1

5060의 '하고 싶은 것'을 실행으로 연결하는 온디맨드 메이트 플랫폼

- **문서 목적**: 모두의 창업 2기 지원용 MVP 제작 및 초기 사용자 검증
- **제품 단계**: 아이디어 검증 → 인터랙티브 MVP 제작
- **MVP 지역**: 서울
- **핵심 사용자**: 50~69세 / **Mate**: 20~40대 중심

---

## 1. Product Vision

**제품 한 줄 정의**
HeyDay는 5060이 배우고, 만들고, 경험하고 싶은 일이 생겼을 때 검증된 20~40대 메이트를
직접 골라 부르는 플랫폼이다.

**핵심 메시지**
기존 시니어 서비스가 "무엇을 도와드릴까요?"라고 묻는다면,
HeyDay는 "오늘 무엇을 해보고 싶으세요?"라고 묻는다.

**제품 철학**
시니어를 돌봄의 대상이 아니라, 자신의 시간과 돈을 어디에 쓸지 결정하는
능동적인 소비자이자 실행자로 본다.

## 2. Problem

돌봄과 혼자 하기 사이에 빈칸이 있다. 건강하고 활동적인 5060에게도 혼자 시작하기
어려운 일이 있다 — 챗GPT를 제대로 배우기, 스마트폰·새 앱 배우기, 유튜브 시작하기,
SNS·숏폼 만들기, 경험을 강의로 만들기, 작품으로 전시 열기, 영화·전시·공연 함께 즐기기,
새로운 취미 시작하기.

간병이나 전문 돌봄까지 필요한 일은 아니다. 하지만 스스로 처음부터 해결하기는 어렵고,
매번 자녀에게 부탁하거나 장기 교육과정을 신청하기도 부담스럽다.

## 3. What We Already Know

2024년 디지털 기기 사용·교육 수요 조사에서 생성형 AI, 사진·영상 편집, 디지털 콘텐츠
제작, 유튜브 업로드·운영 등의 학습 요구가 확인됐고, 1:1 코칭·소수 코칭 수요도 나타났다.
현재는 실제 5060을 1:1로 만나며 욕구를 더 구체적으로 확인하고 있다.

실제 사용자 발화: "유튜브를 시작하고 싶어요." "내 경험으로 강의를 하고 싶어요."
"작품으로 전시를 열고 싶어요."

**이미 확인된 것**: 5060에게 배우고, 만들고, 새로운 경험을 시작하려는 욕구가 존재한다.

**아직 검증하지 않은 것**
1. HeyDay Mate에게 실제로 돈을 지불하는가
2. 어떤 활동에 가장 먼저 돈을 쓰는가
3. 적정 가격은 얼마인가
4. 어떤 Mate를 가장 신뢰하고 선택하는가
5. 한 번 이용한 뒤 다시 이용하는가
6. 문화·외출·취미 영역도 유료 수요가 존재하는가

## 4. MVP Goal

예쁜 앱을 만드는 것이 목적이 아니다. 이미 확인한 5060의 '하고 싶은 것'이
실제 유료 예약 행동으로 전환되는지를 검증한다.

**North Star** — 가격을 본 사용자가 실제로 Mate 예약을 요청하는가?

## 5. Target User

**Primary** — 50~69세 액티브 5060. 기본적인 스마트폰 사용 가능, 새로운 기술과 콘텐츠에
관심, 자기결정권이 강함, 자녀에게 계속 부탁하는 것은 부담스러움, 필요할 때 원하는
도움만 받고 싶음. 전문적인 간병·돌봄은 필요하지 않다.

**Secondary** — 30~50대 자녀. 이용권 선물·예약 대행·결제. 다만 MVP의 중심 사용자는
자녀가 아니라 5060 본인이다.

## 6. Mate

20~40대 중심. 나이보다 전문성, 관심사, 커뮤니케이션 능력, 신뢰도, 활동 가능 지역,
이용자 평가를 중시한다.

**프로필 필수 정보**: 이름, 사진, 나이, 활동 지역, 전문 분야, 가능한 활동, 가격,
가능한 시간, 인증 배지, 활동 횟수, 후기·평점

**향후 검증 체계**: 본인 확인, 신원 확인, 인터뷰, HeyDay 기본교육, 활동 카테고리별 검증,
상호평가, 신고·분쟁관리

MVP에서는 실제 개인정보 인증 시스템을 구현하지 않고 '인증 완료' UI만 프로토타입으로
표현한다.

## 7. Initial Categories

| 영역 | 활동 |
|---|---|
| 01. AI·디지털 | 챗GPT, 스마트폰, 앱 사용, 사진 정리, 새로운 디지털 서비스 |
| 02. 콘텐츠·창작 | 유튜브, 숏폼, SNS, 글쓰기, 사진·영상, 강의 콘텐츠 만들기 |
| 03. 문화·외출 | 영화, 전시, 공연, 서점, 카페, 문화행사 |
| 04. 취미·배움 | 새로운 취미, 미술, 외국어, 운동, 관심사 활동 |

## 8. Core User Flow

1. **Home** — 오늘 뭐 해보고 싶으세요? (4개 카테고리)
2. **활동 선택**
3. **시간·지역** — 언제 만나고 싶으세요? / 어디에서 만나고 싶으세요?
4. **Mate List** — 이름·나이·전문분야·활동지역·활동횟수·평점·인증·가능시간·가격
5. **Mate Detail** — 사진, 소개, 전문 분야, 함께 할 수 있는 활동, 인증정보, 후기,
   가능한 시간, 가격 → CTA `이 Mate에게 예약 요청`

## 9. Pricing & Booking

가격은 공개한다. 단, 즉시 결제는 하지 않는다.

가격 확인 → 예약 요청 → Mate 가능 여부 확인 → 예약 확정

가격은 확정값이 아니라 검증용 가설이다.

- AI·디지털: 60~90분 / 3만~4만원대
- 콘텐츠 제작: 90분 / 3만~5만원대
- 문화·취미: 2시간 / 4만~6만원대

## 10. Business Model

- **Phase 1 — B2C**: 이용 건별 플랫폼 매칭 수수료(가설: 결제액의 약 20~25%)
- **Phase 2 — Family**: 자녀의 이용권 선물·예약·패키지 구매
- **Phase 3 — B2B**: 기업 임직원 부모 대상 가족복지 프로그램
- **Phase 4 — B2G**: 지자체·기관 대상 디지털 포용, 세대 연결, 액티브 시니어, 평생학습

## 11. 서울 운영 전략

서비스 화면에서는 서울 전 지역을 제공한다. 단 초기 운영은 실제 사용자와 Mate가 모이는
2~3개 권역에 밀도를 집중한다(도심권: 종로·중구·용산·서대문·마포 / 동남권: 강남·서초·
송파·강동). 이후 수요 데이터를 보고 확장한다.

## 12. MVP 기능

홈, 카테고리 선택, 활동 선택, 지역 선택, 날짜·시간 선택, Mate 목록, Mate 상세,
가격 표시, 예약 요청, 예약 완료 화면.

**Mock Data** — Mate 8명 내외. 서로 다른 연령·전문 분야·지역·가격·후기·인증 정보.

## 13. MVP에서 만들지 않을 것

실제 회원가입, 실제 신분증 인증, 실제 결제, 실시간 GPS, 실시간 채팅, AI 추천 알고리즘,
복잡한 관리자 페이지, 병원 동행, 간병, 신체보조, 금융거래 대행, 비밀번호 입력 대행.

특히 간병·의료·금융 영역은 HeyDay 초기 서비스 범위에서 제외한다.

## 14. Success Metrics

**Primary** — 가격 공개 후 예약요청 전환율

**Secondary** — 가장 많이 선택한 카테고리, 예약 요청률, 실제 매칭 성사율, 적정 가격대,
Mate 선택 기준, Mate별 선택률, 재이용 의향, 실제 재예약률, 평균 이동거리·시간,
사용자 만족도

## 15. MVP UX Principles

**반드시 지킬 것** — 큰 글씨, 큰 버튼, 화면당 선택지 최소화, 한 화면에 하나의 핵심 행동,
복잡한 메뉴 금지, 가격 명확 표시, 어려운 IT 용어 최소화, 뒤로가기 명확 제공,
예약 과정 5단계 이내, 모바일 우선.

**디자인 방향** — 따뜻하지만 '노인 서비스'처럼 보이지 않는다.
피할 것: 병원 이미지, 간병 이미지, 과도한 효도·보호 메시지, 지나치게 큰 노인용 UI 느낌,
뻔한 보라색 AI 그라데이션, SaaS 대시보드 디자인.
원하는 인상: 당근의 친근함 + Airbnb의 경험 선택 + 현대적인 라이프스타일 서비스.

## 16. Founder Advantage

김연지는 11년간 기자로 사람과 사회의 문제를 취재했고, IT·AI 기업에서 기술과 사용자를
연결하는 커뮤니케이션을 경험했으며, 현재 실제 5060에게 AI와 콘텐츠 제작을 가르치고 있다.
1:1 만남을 통해 이들의 다음 목표를 직접 듣고 있고, 책·숏폼·브런치·SNS 등 실제 실행
결과가 나오는 과정을 경험하고 있다. 따라서 초기 고객을 광고로 상상하는 것이 아니라,
지금 만나고 있는 사용자에게 직접 MVP를 보여주고 검증할 수 있다.

## 17. PRD 핵심 가설

| 영역 | 가설 | 상태 |
|---|---|---|
| Problem | 5060에게는 하고 싶은 일이 있지만 처음 실행할 때 함께해 줄 사람이 부족하다 | 일부 검증 |
| Solution | 필요할 때 검증된 Mate를 직접 선택하면 실행 장벽을 낮출 수 있다 | 검증 필요 |
| Business | 5060은 이 경험을 위해 직접 비용을 지불한다 | 검증 필요 |
| Retention | 만족한 사용자는 동일하거나 다른 Mate를 다시 부른다 | 검증 필요 |

**MVP가 답해야 할 네 가지 질문**

1. 5060은 무엇을 가장 먼저 하고 싶어 하는가?
2. 어떤 Mate를 선택하는가?
3. 얼마까지 지불하는가?
4. 한 번 이용한 뒤 다시 이용하는가?
