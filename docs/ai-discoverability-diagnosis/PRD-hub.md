# PRD — AI 프로필 허브 (AI Profile Hub)

> 홈페이지가 없는 사업자를 위해 **AI가 읽어가도록 설계된 단 하나의 공식 정보 페이지**를 발행하고,
> 실제로 읽혔는지 · 인용됐는지 · 점수가 올랐는지까지 관측한다.

| 항목 | 내용 |
|---|---|
| 문서 버전 | v0.1 (초안) |
| 작성일 | 2026-09-07 |
| 상태 | 검토 대기 — 하단 [9. 오픈 이슈](#9-오픈-이슈) 답변 후 확정 |
| 상위 문서 | [PRD.md](PRD.md) — 진단 본체 (F1~F10) |
| 이 문서의 범위 | 허브 기능 F11~F15. 진단 로직은 다루지 않는다 |

---

## 0. 이 문서가 따로 있는 이유

상위 PRD의 **F1~F10은 전부 진단**이다. 입력 · 자산 수집 · 질문 생성 · 응답 측정 · 채점 · 근거 규율 ·
개선 산출물 · 리포트 · PDF · 재진단. 허브는 **F번호가 없고**, 표 한 줄
(`| 연결 안 됨 | 자산은 있는데 서로 이어지지 않음 | 허브 페이지·상호 링크 |`)로만 스쳐 지나간다.

그런데 코드에는 이미 들어와 있다.

```
lib/hub.ts               372줄   초안 생성 · 발행 게이트 · JSON-LD · llms.txt · 완성도 점수
lib/hubEffect.ts         166줄   발행→수집→인용→점수 4단계 효과 측정
lib/crawlers.ts           85줄   AI 봇 22종 식별 · robots.txt 생성
app/p/[slug]/page.tsx    244줄   공개 페이지 (JSON-LD · rel=me · 크롤 로깅)
app/(app)/.../hub/page   786줄   편집 화면
```

**명세 없이 구현된 기능이라 "완성"의 기준이 없다.** 그래서 다 만들었는데도 안 끝난 것처럼 느껴진다.
이 문서는 그 기준을 만든다. 새로 만들 것보다 **이미 만든 것을 확정하는 분량이 더 많다.**

## 1. 지금 상태 — 이미 구현된 것

아래는 재논의 대상이 아니다. 동작하며, 이 PRD의 전제다.

| 영역 | 구현 내용 | 위치 |
|---|---|---|
| 초안 생성 | 최신 리포트에서 허브 초안 자동 생성. **모르는 정보는 지어내지 않고 비운다** | `lib/hub.ts:draftFromReport` |
| 발행 게이트 | `[초안]` 표식이 남았거나 빈 FAQ·서비스가 있으면 발행 차단 | `lib/hub.ts:canPublish` |
| 완성도 점수 | 6개 항목 체크리스트 → 0~100점. 자동 초안은 미완성으로 계산 | `lib/hub.ts:hubReadiness` |
| 구조화 데이터 | schema.org `@graph` — 엔터티(sameAs · knowsAbout · areaServed) + ProfilePage + FAQPage | `lib/hub.ts:buildJsonLd` |
| 동명이인 분리 | `disambiguatingDescription`으로 동명 주체와 분리 선언 | 같음 |
| llms.txt | 허브별 평문 요약 `/p/{slug}/llms.txt` | `app/p/[slug]/llms.txt/` |
| robots.txt | AI 크롤러 22종을 **명시적 Allow** (일반 SEO와 반대 방향) | `lib/crawlers.ts:buildRobotsTxt` |
| sitemap.xml | 발행된 허브만 색인 대상으로 노출 | `app/sitemap.xml/` |
| 크롤 관측 | UA로 봇 식별 → 사업자·목적(학습/실시간조회/색인)별 기록 | `lib/crawlers.ts` + `hub_crawls` 테이블 |
| 효과 측정 | 발행 → 수집 → 인용 → 점수변화 4단계를 **관측된 사실로만** 판정 | `lib/hubEffect.ts` |
| 영속성 | `DATA_DIR` 볼륨 마운트로 배포 후에도 URL 유지 | `lib/db.ts`, `DEPLOY.md` |

**이 구현의 강점 두 가지는 유지한다.**

1. **지어내지 않는다.** 자동 문구에 `[초안]` 표식을 붙이고, 표식이 남으면 발행을 막는다.
   허브는 "AI가 참조할 공식 출처"이므로, 검증 안 된 문구가 공개되면 **아무것도 없는 것보다 나쁘다.**
2. **인과를 단정하지 않는다.** `hubEffect`는 수집·인용·점수를 **각각 별도 지표로** 관측한다.
   UA는 위조 가능하므로 "보장"이 아니라 "관측치"로 표기한다.

## 2. 진짜 문제 — 페이지는 있는데 발견되지 않는다

허브의 작동 원리는 `lib/hubEffect.ts`에 이미 명시돼 있다.

```
발행 → AI 크롤러가 수집 → AI 답변이 허브를 인용 → 노출·정확도 점수 상승
```

**1단계와 2단계 사이가 끊겨 있다.**

크롤러는 링크를 타고 온다. 그런데 지금 허브의 링크 구조는:

| 방향 | 상태 |
|---|---|
| 허브 → 채널 (`sameAs`, `rel=me`) | ✅ 구현됨 |
| 채널 → 허브 (역링크) | ❌ **없음** |
| 외부 인바운드 링크 | ❌ **0개** |
| 검색엔진 색인 제출 | ❌ 미연동 |

인바운드 링크가 0인 새 URL을 GPTBot이 찾아올 이유가 없다.
제품 스스로도 그걸 알고 있다 — `awaiting_crawl` 단계의 안내 문구가 이렇게 적혀 있다:

> "발행 직후에는 수집까지 **며칠에서 몇 주**가 걸립니다."

**30일 재진단 루프에서 '몇 주'는 창 전체를 태운다.**

그래서 지금 구조가 실제로 도달할 가능성이 가장 높은 결말은 이것이다.

```
발행 → (아무도 안 옴) → 30일 후 재진단 → 점수 그대로 → "효과 없네"
```

제안서가 "이 흐름의 핵심은 ⑥번(재진단)"이라고 말하는데, **그 ⑥번이 0을 반환한다.**

> **허브가 미완성인 이유는 페이지가 덜 예뻐서가 아니라, 발견 경로가 설계되지 않아서다.**
> 남은 작업의 대부분은 페이지 안이 아니라 **페이지 바깥**에 있다.

### 부수적으로 확인된 결함

| # | 결함 | 영향 |
|---|---|---|
| D1 | 루트 `/llms.txt` 없음 (허브별 경로만 존재) | llms.txt 규약의 표준 위치가 비어 있어 에이전트가 사이트 단위로 못 읽음 |
| D2 | OG 이미지 없음 (`openGraph`에 `images` 미설정) | **카톡으로 공유하면 미리보기가 안 뜬다.** 사장님의 1차 배포 경로가 카톡이다 |
| D3 | 발행 후 행동 안내 없음 | URL만 주고 "이걸 어디에 붙여야 하는지"를 말해주지 않는다 |

## 3. 목표와 비목표

### 3.1 목표

| # | 목표 | 성공 기준 |
|---|---|---|
| H1 | 발행된 허브가 **실제로 수집된다** | 발행 후 14일 내 AI 크롤러 1개 이상 방문 기록 ≥ 70% |
| H2 | 사장님이 역링크를 **실제로 건다** | 발행 후 7일 내 채널 1개 이상에서 허브 URL 검출 ≥ 50% |
| H3 | 역링크 여부를 **시스템이 검증한다** | 자가신고 아님. 채널 페이지를 페치해 허브 URL 포함 여부 자동 확인 |
| H4 | 30일 재진단에서 **변화가 관측된다** | 허브 발행+역링크 완료 집단의 총점 변화 중앙값 ≥ +5점 |
| H5 | 공유 가능한 물건이 된다 | 카톡·문자 공유 시 미리보기 카드 정상 표시 |

**H3이 이 PRD의 성격을 규정한다.** 상위 PRD의 F6(근거 규율)과 같은 원칙이다 —
"하셨나요?"라고 묻지 않고 **직접 확인한다.** 사장님이 안 걸었으면 안 걸었다고 말해준다.

### 3.2 비목표

- **채널 자동 수정.** 인스타·네이버 플레이스에 대신 써넣지 않는다. 쓰기 권한을 받지 않는 원칙(상위 PRD 3.2)을 유지한다.
- **백링크 구매·교환.** 어떤 형태의 인위적 링크 조작도 하지 않는다. 스팸이고, 발각 시 도메인 전체가 죽는다.
- **크롤러 유입 보장.** AI 사업자의 수집 정책은 우리가 통제할 수 없다. **관측만 하고 약속하지 않는다.**
- **허브 CMS.** 블로그·게시판·이미지 갤러리를 만들지 않는다. 허브는 **한 장**이다.
- **커스텀 도메인.** v2 이후. 지금은 `/p/{slug}`로 충분하다.

## 4. 기능 명세

### F11. 역링크 유도와 검증 ★ 최우선

**발행 다음 화면은 "축하합니다"가 아니라 "이제 이걸 여기에 붙이세요"여야 한다.**

허브는 이미 사장님의 채널 목록(`hub.links`)을 갖고 있다. 그 목록을 그대로 **할 일 목록으로 뒤집는다.**

| 단계 | 사양 |
|---|---|
| ① 붙여넣기 안내 | 채널별로 **어디에** 붙일지 명시 + 복사 버튼. 인스타 → 프로필 웹사이트 칸 / 네이버 플레이스 → 업체 소개 마지막 줄 / 블로그 → 프로필 링크 / 유튜브 → 채널 정보 |
| ② 문안 제공 | 링크만 주지 않는다. `공식 정보 확인: {URL}` 형태의 한 줄 문안을 함께 준다 |
| ③ 검증 | 각 채널 URL을 페치해 허브 URL 문자열 포함 여부를 확인. **결과를 ○/× 로 표시** |
| ④ 재검증 | 편집 화면에서 언제든 "다시 확인" 실행. 검증 시각을 함께 기록 |

**검증은 자가신고를 대체한다.** "붙이셨나요? [예]" 버튼은 아무 정보가 아니다.
직접 페치해서 확인하면, 사장님이 착각했거나(엉뚱한 칸에 넣음) 플랫폼이 링크를 막은 경우까지 잡힌다.

**페치 실패는 미완료가 아니다.** robots 차단·로그인 필요·JS 렌더링 등으로 확인이 불가능한 채널은
`확인 불가`로 별도 표기한다. 상위 PRD의 '수집 불가' 처리 원칙과 동일하다.
**확인 못 한 것을 안 한 것으로 취급하지 않는다.**

### F12. 루트 `/llms.txt`

llms.txt 규약의 표준 위치는 **도메인 루트**다. 지금은 `/p/{slug}/llms.txt`만 있어서
사이트 단위로 읽으려는 에이전트가 빈손으로 돌아간다.

```
/llms.txt        ← 신설. 서비스 소개 + 발행된 허브 목록(링크)
/p/{slug}/llms.txt  ← 기존 유지. 개별 브랜드 상세
```

루트 llms.txt는 **허브 디렉터리 역할을 겸한다.** 에이전트가 한 번의 요청으로
"이 사이트에 어떤 브랜드의 공식 정보가 있는가"를 파악할 수 있어야 한다.

### F13. 능동 색인 신호와 허브 디렉터리

사장님의 숙제에만 의존하면 안 된다. **우리가 직접 걸 수 있는 링크부터 건다.**

| 수단 | 내용 | 비용 | 기대 |
|---|---|---|---|
| **허브 디렉터리** `/p` | 발행된 허브 전체를 나열하는 공개 색인 페이지 | 낮음 | **모든 허브가 최소 1개의 인바운드 링크를 확보한다.** 자체 해결 가능한 유일한 수단 |
| IndexNow | 발행 시 Bing·Yandex에 URL 1건 POST | 낮음 | 불확실. 저렴하니 한다 |
| 검색 콘솔 등록 | 구글 Search Console · 네이버 서치어드바이저에 sitemap 제출 | 1회 수동 | 중간 |
| sitemap `lastmod` | 이미 구현됨 (`app/sitemap.xml`) | — | 유지 |

**허브 디렉터리가 핵심이다.** 허브가 100개 쌓이면 디렉터리 자체가 크롤 가치가 있는 페이지가 되고,
**새로 발행된 허브는 그날부터 링크를 받는다.** 12월 본선 목표인 "실측 점포 100곳"이
그대로 이 자산이 된다 — 진단을 많이 할수록 각 허브의 발견 가능성이 함께 올라간다.

> 단, 디렉터리는 **발행된 허브만** 싣는다. 미발행·비공개 허브는 노출하지 않는다.

### F14. 공유 미리보기 (OG 이미지)

사장님이 허브를 배포하는 1차 경로는 검색이 아니라 **카톡**이다. 지금은 미리보기가 비어 있다.

- `/p/{slug}/opengraph-image` 동적 생성 — 상호 · 한 줄 정의 · 지역 · 키워드를 담은 1200×630 카드
- Next.js `ImageResponse` 사용 (별도 이미지 저장소 불필요)
- 한글 폰트는 PDF 렌더링에 이미 내장돼 있으므로 재사용

### F15. 발행 후 30일 트랙

`lib/hubEffect.ts`의 5단계(`not_published → awaiting_crawl → crawled → cited → measured`)는
이미 관측되고 있다. 여기에 **사장님이 볼 일정**을 붙인다.

| 시점 | 화면이 말하는 것 |
|---|---|
| D+0 발행 직후 | F11 역링크 할 일 목록. **여기서 이탈하면 나머지가 전부 무의미하다** |
| D+3 | 역링크 검증 결과. 미완료 채널만 다시 안내 |
| D+7 | 크롤 관측 현황 — "누가 읽어갔는가" |
| D+30 | 재진단 실행 유도 → 점수 변화 |

**D+0의 이탈률이 이 제품의 진짜 KPI다.** 발행하고 아무것도 안 붙인 사장님은
30일 뒤 "효과 없다"는 결론만 얻고 떠난다.

## 5. 완성의 정의 (릴리스 게이트)

아래를 **전부** 통과해야 "허브 완성"이라고 말한다.

**기능**
- [ ] F11 역링크 안내가 발행 직후 화면에 뜬다
- [ ] F11 역링크 검증이 채널을 실제로 페치해 ○/×/확인불가를 판정한다
- [ ] F12 루트 `/llms.txt`가 200을 반환하고 발행 허브를 나열한다
- [ ] F13 `/p` 디렉터리가 발행 허브 전체를 링크한다
- [ ] F14 OG 이미지가 카톡·슬랙에서 카드로 렌더된다
- [ ] F15 발행 후 단계별 안내가 `hubEffect.stage`에 연동된다

**정합성** — 세 곳의 URL이 **완전히 일치**해야 한다. 하나라도 어긋나면 구조화 데이터가 무효다.
- [ ] `<link rel="canonical">` (`generateMetadata`)
- [ ] JSON-LD `@id` / `url` (`buildJsonLd`)
- [ ] `sitemap.xml`의 `<loc>`
- [ ] 한글 슬러그의 퍼센트 인코딩이 위 세 곳에서 동일하게 처리된다

**검증**
- [ ] 발행된 허브를 [Schema.org Validator](https://validator.schema.org/)와 Google 리치 결과 테스트에 통과시킨다
- [ ] `curl -A "GPTBot" {허브URL}` 로 크롤 기록이 남는 것을 확인한다
- [ ] 배포 재기동 후에도 발행 URL이 살아 있다 (볼륨 영속성 실증)

**안전장치 (기존 유지 확인)**
- [ ] `[초안]` 표식이 남은 허브는 여전히 발행되지 않는다

까지 시연할 수 있으면 다른 팀과 갈린다. 대부분의 GEO 도구는 측정에서 멈춘다.

## 7. 리스크

| # | 리스크 | 대응 |
|---|---|---|
| R1 | **크롤러가 끝내 안 온다** | 우리가 통제 못 하는 영역. `hubEffect`가 이미 단계별로 분리 관측하므로, 수집이 안 됐으면 "안 됐다"고 그대로 표시한다. 점수 상승을 약속하지 않는다 |
| R2 | 역링크 검증이 대부분 '확인 불가'로 나온다 | 인스타·네이버 플레이스는 JS 렌더링·로그인 벽이 있다. 확인 가능한 채널(블로그·홈페이지·유튜브)부터 지원하고, **불가는 불가로 정직하게 표기**한다 |
| R3 | 허브 디렉터리가 스팸 색인으로 취급 | 발행 허브만, 완성도 게이트 통과분만 싣는다. 자동 생성 문구는 애초에 발행이 막혀 있다 |
| R4 | 사장님이 D+0에서 이탈 | 할 일을 **3개 이하**로 자른다. 채널이 5개여도 효과가 큰 순으로 3개만 먼저 보여준다 |
| R5 | 허브 정보가 낡아 오히려 오정보가 됨 | `dateModified` 노출은 이미 구현. D+30 재진단 시 기준선 재확인을 강제한다 |

**R5는 제품 철학과 직결된다.** 우리는 "AI가 틀리게 말한다"를 문제로 정의한 서비스다.
**우리가 발행한 페이지가 낡아서 틀린 정보의 출처가 되면 자기모순이다.**

## 8. 지표

**북극성** — 허브 발행 후 30일 재진단에서 **총점이 오른 비율**

보조 지표:

| 지표 | 정의 | 목표 |
|---|---|---|
| 역링크 완료율 | 발행 후 7일 내 채널 1개 이상 검증 통과 | ≥ 50% |
| 수집 도달률 | 발행 후 14일 내 AI 크롤러 1회 이상 방문 | ≥ 70% |
| 인용 채택률 | 재진단 증거 중 허브 URL을 인용한 비율 | 관측만 (목표 미설정) |
| D+0 이탈률 | 발행 후 역링크 안내에서 아무 행동 없이 이탈 | ≤ 40% |

**인용 채택률에 목표를 두지 않는 이유.** AI 답변의 출처 표기는 엔진·시점에 따라 요동친다.
목표를 걸면 숫자를 만들고 싶어지고, 그 순간 이 제품의 유일한 자산인 정직성이 깨진다.
